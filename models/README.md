# Stem separation models

Generated by `tools/model-export/export_htdemucs.py` from Meta's open Demucs v4 checkpoints
(MIT licence): `htdemucs` (fast), `htdemucs_ft` (4 fine-tuned models, best quality, default),
`htdemucs_6s` (6 sources). Each model is exported as CoreML (`.mlmodelc`, fp32, GPU) and ONNX
(`.onnx`, CPU fallback) plus a JSON manifest. They are not checked into git (≈3 GB); recreate:

```sh
cd tools/model-export
uv venv .venv --python 3.11
uv pip install --python .venv/bin/python torch==2.5.1 torchaudio==2.5.1 demucs==4.0.1 onnx==1.17.0 onnxruntime==1.20.1 coremltools==8.3 onnxscript soundfile "numpy<2"
for m in htdemucs htdemucs_ft htdemucs_6s; do TORCH_HOME=$PWD/cache .venv/bin/python export_htdemucs.py --model $m --out ../../models; done
```

## Runtime (crates/stems)

`clubcraft-stems` loads `<name>.json` and then either `<name>[_i].mlmodelc` (CoreML, macOS,
CPU+GPU, preferred) or `<name>[_i].onnx` (ONNX Runtime 1.20 CPU, fallback). The `.mlpackage`
directories are only needed to recompile the `.mlmodelc` (`xcrun coremlcompiler compile`).
The `htdemucs_ref_*.npy` tensors are used by `cargo test -p clubcraft-stems --test reference`.

| preset | model | passes | time for a 5:17 track on M1 Pro (CoreML) |
|---|---|---|---|
| `Quality::Fast` | `htdemucs` | 1 shift, overlap 0.25 | ~17 s (18x realtime) |
| `Quality::High` (default) | `htdemucs_ft` | 1 shift, overlap 0.25 | ~80 s (4x) |
| `Quality::Ultra` | `htdemucs_ft` | 2 shifts, overlap 0.5 | ~245 s (1.3x) |
